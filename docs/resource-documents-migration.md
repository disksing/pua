# 资源文档迁移与回退

Workspace、Project、Task 的创建输入和模板写入 `spec.md`，Agent 的上下文和对话事项写入 `memory.md`。旧资源的整份正文按字节保留在 Memory 的来源块中。缺失的 Spec 使用统一迁移说明。Scheduler 继续使用 `scheduler.md`，保留既有 `chat.md` 迁移规则。

## 迁移前

1. 结束仍按旧指引工作的 Turn、文件编辑器和其他旧文档写入方。切换服务时按既有部署流程停写，备份旧二进制、配置、Workspace 文件和控制数据。
2. 在副本上执行预检。清点开放和归档资源的 `workspace.md`、`project.md`、`task.md`、`chat.md`、`spec.md`、`memory.md` 及 `.pua-legacy-documents`。记录原字节哈希并排查符号链接、目录和异常权限。审阅托管块之外仍要求维护旧文件的 `AGENTS.md` 文本。
3. 用相同版本在副本的 Workspace 根目录运行 `pua migrate`。检查新 Spec、核对 Memory 原正文和对话事项、验证旧链接。重跑一次并比较两次 `spec.md` 和 `memory.md` 的哈希。检查遗留暂存和 `pua doctor` 的 `legacy_document_pending`。

## 断点、晚到写入与旧链接

迁移将旧文件原子改名到同资源的 `.pua-legacy-documents/` 暂存路径。Memory 原子持久化后会复核写入和暂存内容，再退役暂存。中断时可重跑 `pua migrate`。新 Turn 刷新指引时也会处理 Workspace 和当前资源的晚到旧文件。

同源相同内容只导入一次。同源的新版本替换仍与原哈希匹配的导入块，保留 Memory 其余内容。日常记忆可写在导入块之外。修改历史事项时保留两侧迁移标记。若旧文件和 Memory 内的同一块都发生编辑，迁移保留两侧并报冲突。备份两侧后人工合并，先把只存在于 Memory 的改动保存在块之外，再把块正文替换为暂存稿的完整原文并保留标记。重跑后校对最终正文及事项。

Web 预览和原文下载将旧资源说明路径只读映射至 Memory。旧路径对应的是包含原文的当前 Memory。命令行直接读取旧路径应改用 `memory.md`。

## 授权与回退

普通文档保存入口只接受 Memory 和原有允许的模板、产物路径。Spec 的单独保存入口验证同源请求、所选 Workspace 用户、归属和基准哈希。Agent 按托管指引核对可追溯的用户指示或批准，范围仅限指定改动。所选用户名源于本地界面，文件系统仍沿用同 UID 权限。任意同 UID 进程有能力直接修改磁盘和模拟本地请求。应用写锁只协调 PUA 支持的写入路径。正式迁移须停掉可能持有旧文件描述符的直接写入方。

若需要回退，暂停新写入并单独保存迁移后的 Spec、Memory、暂存稿及控制数据。恢复配套的旧程序和迁移前备份。迁移后新增的规格变更、事项和上下文先在副本中逐项合并至恢复的旧说明，再验证历史和事项。使用旧程序直接打开已迁移目录可能重新建立旧路径。在隔离副本完成验证后再按部署流程切换。
