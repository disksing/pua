# Telegram 聊天接入

每个 Workspace 可以连接一个专用 Telegram 机器人。个人私聊中的话题分别对应 Workspace、Project 或 Task；话题和网页使用同一个 PUA 用户的资源聊天。Telegram 输入与 Agent 公开答复会出现在网页；网页的新用户消息与 Agent 公开答复也会同步到已连接的话题。执行日志和工具输出不转发。

## 配置

1. 在 Telegram 的 BotFather 创建一个专用机器人，开启 Topics 或 Threaded Mode。不要同时把这个机器人交给其他轮询程序或 Webhook 服务。
2. 打开 PUA 的 Settings，选择 Workspace，在对应 Workspace 下展开 Telegram。Workspace 资源自身的 Settings 中也有相同入口。
3. 填入 Bot Token，选中启用并保存。保存时验证机器人身份、话题模式与 Webhook 状态；已有 Webhook 会阻止启用，不会自动删除它。
4. 选择与网页聊天相同的 Workspace 用户（默认选中当前网页用户），创建配对链接，用自己的 Telegram 账号打开。链接有效期十分钟、只能使用一次，持有链接的人可绑定该用户，因此不要转发。
5. 配对后在机器人中选择 Workspace、最近聊天或浏览项目，也可发送 `/search` 加任务名称或编号。刷新 PUA 设置页可查看配对结果与最近成功连接时间。

一个 Telegram 账号在同一 Workspace 内只能绑定一个 PUA 用户，一个 PUA 用户也只能绑定一个 Telegram 账号。更换身份前先解绑。不同 Workspace 使用不同机器人。

## 使用话题

| 操作 | 命令或入口 |
| --- | --- |
| 导航菜单 | `/menu` 或 `/help` |
| Workspace 总览 | `/open workspace` |
| 打开指定资源 | `/open project1.task1` |
| 浏览项目 | `/projects`，再点 Tasks 浏览任务 |
| 最近打开的聊天 | `/recent` |
| 查找项目或任务 | `/search` 后加关键词 |
| 查看话题对应资源及状态 | `/status` |
| 暂停本话题推送 | `/stop` |
| 恢复接收新回复 | `/resume` |
| 话题被删或创建结果不确定时修复 | 在新话题内发送 `/bind project1.task1` |

首次打开资源时按需创建话题，不会自动创建全部任务的话题，也不会倒灌旧消息。打开已有资源会在它的话题中提示继续聊天；Telegram 客户端可能需要手动点进该话题。搜索每次显示最多八条结果，结果过多时缩小关键词；项目与最近聊天列表支持翻页。

打开话题后，网页端的新用户消息和公开答复都会推送；网页用户消息标注用户名与 `(web)`，Telegram 发来的输入不会再次回显。两端必须选择同一 Workspace 用户；如 Telegram 绑定 `User` 而网页使用 `disksing`，记录会按用户隔离。设置页会提示身份不一致，可切换网页用户查看原记录，或先解绑再按正确用户配对；重新配对不会自动合并两个用户的旧历史。Telegram 投递成功不会自动清除 PUA 的未读标记。`/stop` 只暂停推送，不停止 Agent；关闭 PUA Chat 会撤销当前聊天周期的回复权限。`/resume` 从最新位置开始接收，跳过暂停期间的旧回复。

`/bind` 是显式修复操作：把同一资源移到当前话题后，旧话题不再路由输入，未完成的旧投递不会转移。一个已经绑定其他资源的话题不能被直接改成新资源。

首版仅处理个人私聊中的文字。群聊、语音识别、图片和文件上传不在此版本范围；手机处于外网时，回复中的局域网产物链接不一定能访问。

## 连接与恢复

PUA 使用长轮询，从运行 Server 的机器主动连接 Telegram，不需要开放入站公网端口。出站代理沿用运行 Server 进程的 `HTTPS_PROXY` 等标准 HTTP 代理环境配置。Telegram 最多保留二十四小时的未获取更新，长期停机不能保证恢复期间所有输入。

机器人 Token、配对状态、话题映射、更新游标和待发送记录保存在 PUA Server 配置文件旁的 `telegram/` 目录，目录权限为 `0700`，文件权限为 `0600`。设置接口不返回原始 Token，错误信息不包含带 Token 的请求地址。迁移 Server 时应把此目录作为敏感运行数据一同备份；不要放进代码仓库。

输入使用稳定消息 ID 去重，Chat 和 Agent 待派发输入一起保存。公开答复逐段保存发送进度，长文本以纯文本分段，遇到 429 按接口要求退避。暂停整个连接会保留话题与待处理状态；解绑用户或断开机器人则撤销对应接入。

网络中断可能发生在 Telegram 已收到消息、PUA 尚未收到响应之间，因此无法保证端到端恰好发送一次。该类投递会显示在设置页中并暂停自动重试。先查看 Telegram，再选择重试或跳过；重试可能产生重复消息。重启时发现未完成的发送也按此规则处理。

设置中的“断开机器人”会删除本地 Token、配对和话题映射，不删除 PUA 聊天历史或 Telegram 中已有的消息。切换为另一个机器人前需要先断开。

## 验证边界

自动化测试使用独立临时 Workspace、模拟 Telegram HTTP 接口及浏览器请求，不需要真实 Token。实际使用时仍须验证自己的 Telegram 客户端支持话题，并确保 Server 能访问 Telegram。当前服务的 Settings 遵循 PUA 既有可信本地或局域网管理边界，不能直接公开到互联网。
