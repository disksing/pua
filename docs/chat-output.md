# Chat 自动输出同步

用户 Chat 开启的 Turn 固定本轮受众及聊天开启周期。PUA 自动同步其完整普通文本块；推理、工具内容和内部 Turn 的输出保留在执行历史。文本块完成、出现后继条目或 Turn 进入终态时，才将相应文本视为完整。

## 输出通道与恢复

Server 为未结 Turn 工作维护独立的输出核对循环，复用 AgentHub 的单 Turn 查询和原有工作结算规则。它独立于会话列表轮询、全量审计、一般消息投递及 Scheduler。

- 新输入准备执行、确定 Turn ID，以及观察到新的 canonical Turn 终态时，立即请求核对对应资源。
- 输出尚未结算时，默认每次核对完成后等待 2 秒重试；稳定空闲的会话也保留此节奏。
- 同一资源的请求合并，最多有一个排队或正在执行的输出核对；资源之间使用独立 controller，慢资源不会让其他资源等待其执行结束。排队和执行中的任务数量按未结资源数有界。
- Server 启动时单独读取持久 Turn work 记录以恢复未结工作，无须先等待完整会话审计。单个损坏记录会报告错误并继续其余记录；周期性全量审计仍保留恢复兜底。
- 输出核对仅推进既有工作及其结算副作用，不重新投递原始用户输入。产生的通知和续接沿原有稳定消息 ID 处理。

发布仍检查资源归档及 Chat 开启周期，使用 session、Turn 和文本块起始事件计算稳定消息 ID。重放、重启或重复唤醒不会产生重复 Chat 消息；关闭后重新开启聊天不会补入旧周期输出。暂停及取消续接沿现有工作状态规则处理。

输出通道参与 Server 关停。排队任务使用生命周期 context，已取消的排队核对不会执行；进行中的 AgentHub 请求受生命周期及 30 秒请求预算约束。

2 秒是无额外唤醒时的重试间隔，不是端到端响应时限。同一资源内既有 controller 工作、磁盘操作、全局 Chat 存储锁及 AgentHub 响应仍可能带来等待。

## 诊断记录

Turn work 记录增加以下可选字段，旧记录可直接读取，不需要迁移：

| 字段 | 含义 |
| --- | --- |
| `createdAt` | 本次工作创建时间；旧工作可能为空 |
| `terminalObservedAt` | PUA 首次从 Turn 投影观察到终态的时间 |
| `lastPublishedAt` | 最近一次成功新增 Chat 输出的消息创建时间 |

Server 日志记录必要标识和计时，不输出消息正文或 Chat 凭据：

- `reconcile timing`：超过 1 秒的冷审计、快速会话轮询或 mailbox 核对的开始时间和总耗时。
- `Turn output reconcile`：超过 1 秒的资源队列等待或执行耗时，以及执行失败。
- `Turn output query`：失败或超过 1 秒的单 Turn 查询耗时。
- `Turn output published`：新增输出时的查询耗时、AgentHub 终态时间、PUA 观察时间、发布消息时间及终态到发布的时差。非终态输出或旧投影缺少终态时间时，时差值为 0。
- `Turn output pending`：每 30 秒记录未结资源数、正在执行或排队的核对数，以及最老未结工作的年龄。该年龄包含 Agent 正在工作的时间，不代表最终回复的滞留时间。

发生延迟时，先对比 AgentHub 终态、PUA 观察与发布时间，再结合队列、查询和审计耗时定位。Chat 已落盘之后的浏览器显示延迟需要另查浏览器网络与页面刷新。
